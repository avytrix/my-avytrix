## Project Overview

Avytrix Technologies corporate website: Next.js 16, React 19, TypeScript, Tailwind CSS 4, pnpm.

Production: GitHub Pages, static export (origin from `NEXT_PUBLIC_SITE_URL`)

## Commands

```bash
pnpm install                      # Install dependencies
pnpm dev                          # Development: http://localhost:3000
pnpm build                        # Production build
pnpm start                        # Start production server
pnpm lint                         # eslint . (flat config; `next lint` is gone in Next 16)
pnpm type-check                   # tsc --noEmit
```

## Deployment

Branch flow (enforced by repo rulesets): feature branch → PR into `develop` (squash) → PR from `develop` into `main` (merge commit). No direct pushes, force pushes or deletions on either; only admins can merge into `main`.

`.github/workflows/ci.yml` runs Lint, Type check, Build site and Source branch on every PR (these job names are the rulesets' required checks; renaming one blocks every PR) and deploys on every push to `main`. It builds a static export (`output: "export"` in `next.config.ts` when `NEXT_OUTPUT=export`, set by CI) and publishes `out/` to GitHub Pages. Images go through the ImageKit loader (`src/lib/imagekit-loader.ts`) for responsive sizes; do not add `static_site_generator: next` to `configure-pages`, it forces unoptimized images.

GitHub Pages is static-only, so the contact form posts to a Cloudflare Worker (`worker/`, at `NEXT_PUBLIC_CONTACT_API_URL`). It verifies reCAPTCHA v3, rate-limits (Upstash, 1/day per IP and email) and sends two Resend templates: `contact-confirmation` to the visitor and `contact-team-notification` to the team. Deploy the Worker with `scripts/deploy-contact-worker.sh` (values from `.env.local`). Templates are generated from `src/lib/email-templates.ts`; after editing them run `npx -y tsx --env-file=.env.local scripts/resend-templates.mts`. Validation rules live in `src/lib/contact-schema.ts`, shared by the form and the Worker.
Any route must be statically renderable: dynamic routes need `generateStaticParams`, and metadata routes need `export const dynamic = "force-static"`.

## SEO / AEO

Follows `seo_and_aeo_engineering_standard.md` (v2.1). Rules that bite:
- Every page builds metadata and JSON-LD from one `seo` object: `pageMetadata(seo)` and `<JsonLd {...seo} crumbs={...} />` (`src/lib/seo.ts`). That gives exactly one `@graph` per page.
- Title ≤ 60 chars ending `| ${siteConfig.name}`; description 140 to 160 chars; both unique.
- Schema and `/llms.txt` (generated by `src/app/llms.txt/route.ts`) may only state facts visible on the site: no invented `sameAs`, addresses, phone numbers, ratings, or FAQ entries.
- Tab and accordion content must stay in the HTML (hide it, don't unmount it).
- `scripts/seo_check.py` runs the gates against `out/` in CI and fails the deploy.

## Architecture

**Pages** (`src/app/`):
| Route | Description |
|-------|-------------|
| `/` | Homepage |
| `/about-us` | About page |
| `/contact` | Contact form with reCAPTCHA v3 |
| `/services` | Services listing |
| `/services/[slug]` | Dynamic service pages |
| `/web-development/[slug]` | Region landing pages (SEO: web development company for USA, UK, Europe, Germany, Australia, Singapore) |
| `/privacy-policy` | Privacy policy |
| `/terms-conditions` | Terms & conditions |

`src/lib/seo.ts` - `pageMetadata()` and `pageGraph()` (single JSON-LD graph)

**Components** (`src/components/`):
- `Header.tsx` - Navigation with mega menu dropdown
- `Footer.tsx` - Multi-column footer
- `Breadcrumb.tsx` - Breadcrumbs (desktop + mobile)
- `ContactForm.tsx` - Form with client + server reCAPTCHA v3 validation
- `CookieConsent.tsx` - Cookie consent banner
- `JsonLd.tsx` - Structured data
- `TechStackTabs.tsx` - Technology stack tabs on homepage
- `FaqAccordion.tsx` - FAQ accordion component
- `ServiceTabs.tsx` - Tabbed content for service pages

**Content** (`src/content/`):
- `home.ts` - Homepage content (hero, services, tech stack, case studies)
- `services.ts` - Service pages data with `getServiceBySlug()` helper
- `locations.ts` - Location landing pages data

**Lib** (`src/lib/`):
- `config.ts` - Site metadata, navigation menus, email config
- `email-templates.ts` - Source HTML for the two Resend templates
- `contact-schema.ts` - Contact form validation (form + Worker)
- `imagekit-loader.ts` - next/image loader for ImageKit

## Environment Variables

Nothing environment-specific is hardcoded: brand name (always `siteConfig.name`, never the literal name, also in titles and copy), site URL, ImageKit base, logo URL, emails, social profiles, reCAPTCHA, contact person (name, phone, optional address), Resend and Upstash Redis all come from env. `src/lib/config.ts` reads them and throws at build if a required one is missing.

- `.env.example` lists every variable; copy it to `.env.local` (gitignored).
- `NEXT_PUBLIC_*` values are inlined at build, so read them as literal `process.env.NEXT_PUBLIC_X`, never `process.env[name]`.
- GitHub: `NEXT_PUBLIC_*` are repo variables (`gh variable set`), mapped in `.github/workflows/ci.yml`; all other values are repo secrets (`gh secret set`). The static build only needs the variables.
- Images: use `` `${siteConfig.cdnUrl}/path` ``, never a literal ImageKit URL.

## Adding New Service Pages

Edit `src/content/services.ts` and add to the `services` array:
```typescript
{
  slug: "new-service",
  title: "New Service",
  metaTitle: `New Service | ${siteConfig.name}`,
  description: "Description for SEO",
  intro: { pageTitle, mainTitle, paragraph, buttonText, buttonUrl, image, imageAlt },
  sections: [] // Optional tabbed content
}
```
